# CLAUDE.md

This file provides guidance to Claude Code when working in [example-apps/dashapps/](.).

## Project Overview

React + TypeScript + Vite app for discovering Dash Platform applications on testnet. A registry data contract holds one `appMetadata` entry per identity per target contract (name, tagline, category, tags, links, icon), one `appEndorsement` per contract naming its **official** publisher, and one `appReview` per identity per contract (1–5 `stars`, optional `title`/`body`). Anyone may describe any contract; only the target contract's owner can endorse, and the endorsed publisher's entry is the official one — every other entry is a **community proposal**. The network enforces all of this with `refersTo` references. Entries are cross-referenced with contract-declared metadata (description + keywords baked into the target contract) and the system Keyword Search contract.

The shell is a six-view app (`discover` / `search` / `category` / `mine` / `add` / `settings`) in [App.tsx](src/App.tsx). Browsing and rating histograms are read-only and need no auth; listing an app or leaving a rating requires signing in with a mnemonic or WIF. Testnet only — mainnet has no default registry and sign-in is rejected there.

## Architecture

`App.tsx` is the orchestrator: it owns view routing and the selected-app detail state, and renders one presentational component per view. Session and network state live in a context provider rather than in `App`. The layers:

## Registry contract

[src/dash/contract.ts](src/dash/contract.ts) holds the schema that Settings → register publishes. All three types are mutable and deletable; the contract is `keepsHistory: false`. Every `contractId` is a required identifier with `refersTo` and listed in its type's `immutable` array.

`appMetadata` — `contractId` (`refersTo` any contract), `name` (required, 1–63), `description` (≤1000), `website` / `repository` / `docs` / `appUrl` (`^https?://`, ≤256), `tagline` (required, 1–120), `category` (required, 16-value enum), `tags` (≤5 comma-separated kebab-case terms), `iconUrl` (`^https://` only). Not transferable or tradeable, so the endorsement's lookup keys never move. Indices:

- `ownerContract` — unique (`$ownerId`, `contractId`); one entry per identity per contract, and the official-entry lookup
- `contractEntries` — (`contractId`), `countable` + `rangeCountable`; the listing total
- `contractRecent` — (`contractId`, `$updatedAt`); a contract's entries
- `recent` — (`$createdAt`); the Discover feed
- `byCategoryRecent` — (`category`, `$createdAt`); the category browser
- `byName` — (`name`); the name-prefix search
- `byOwner` — (`$ownerId`, `$updatedAt`); My submissions

`appEndorsement` — `contractId` (`refersTo` a contract with `owner: "self"`: only its owner may write) and `publisherId` (`refersTo` the publisher's `appMetadata` for this contract, found by `$ownerId` + `contractId`). `publisherId` is mutable so the owner can re-point it; deleting the endorsement withdraws it. Indices: unique `byContract` (`contractId`), `byPublisher`, `recent` (`$createdAt`), `byOwner` (`$ownerId`, `$updatedAt`).

`appReview` — `contractId` (`refersTo` a contract with `owner: "other"`: owners can't review their own), `stars` (required integer 1–5), optional `title` (≤120) and `body` (≤1000). Indices:

- `ownerContract` — unique (`$ownerId`, `contractId`); one review per identity per contract
- `ownerRecent` — (`$ownerId`, `$updatedAt`); a user's reviews
- `contractRating` — (`contractId`), `averageable: "stars"` + `rangeAverageable` + `rankedAverageable` + `rankedCountable`; the proven average, batched averages, `ranked` and `having`
- `contractStars` — (`contractId`, `stars`), `countable` + `rangeCountable`, unranked; the star histogram
- `contractRecent` / `contractStarsRecent` — (`contractId`[, `stars`], `$updatedAt`); review lists, newest first within a star value

`DEFAULT_CONTRACT_IDS.testnet` is `DkpxWsi5D9cP3RvNiF2uMDEhFF3cFCmsVhHXY5HNawkN`; mainnet has no default. Overrides are stored per network under `localStorage['dashapps.contractId.<network>']`. A saved registry without all three document types (one published for an older version of the app) gets a single notice with a "Use the default registry" button instead of the views, so its reads never run; the check is one cached `contracts.getMany` per registry, is skipped for the default, and offers "Try again" if it fails. The registry declares a description (`DECLARED_METADATA`) but no keywords, so it is reached by its configured ID rather than Keyword Search.

## SDK Patterns

- **Proven average** — `sdk.documents.average({ where: [["contractId","==",id]] }, "stars")` returns `count` and `sum` under the key `""`; `ratingAverages` batches a page with `contractId in [...]` + `groupBy: ["contractId"]` (≤100 per call).
- **Star histogram** — `sdk.documents.count({ where: [["contractId","==",id], ["stars","between",[1,5]]], groupBy: ["stars"], orderBy: [["stars","asc"]] })` over `contractStars`, one contract at a time.
- **Rankings** — `leaderboard` calls `sdk.documents.ranked` (avg or count, `direction: "desc"`, `limit` ≤100, optional `offset`); `highlyRated` calls `sdk.documents.having` with `>= 4`. Both group by `contractId`.
- **Official entries** — `endorsementsFor` batches a page's contracts with `contractId in [...]` on `byContract`; the official entry is then `publisherEntry(publisherId, contractId)` on `ownerContract`. `collapseByContract` keeps one row per contract across the loaded pages of Discover and a category, and in Search's name matches, preferring the official entry once it has loaded.
- **Server-ordered paging** — every list goes through `queryPage` in [paging.ts](src/dash/paging.ts): one page in the serving index's order (`desc` for newest first), never re-sorted. It asks for `limit + 1` so "Load more" only shows when another page exists, and passes the last row shown back as the document-ID `startAfter`.
- **Declared contract metadata** — `contractFacts` reads `description`, `keywords`, `version`, and document types off a fetched `DataContract` via `toObject(sdk.version())`; `registerContract` injects them through `DataContract.fromObject` after `setConfig`, since the constructor does not take them.
- **Keyword Search** — the system contract at `BsjE6tQxG47wffZCRQCovFx5rYrAYYC3rTVRWKro27LA`: `contractKeywords` (`keyword == term`, 3–50 chars, paged) and `shortDescription` (`contractId == id`).
- **Document writes** — every write goes through `freshTarget` + `prepare` + `submit` in [documentWrites.ts](src/dash/documentWrites.ts): evict the target contract from the SDK cache and refetch it (returning its owner, so writes can refuse an owner review or a non-owner endorsement before paying for it), then a contract-aware `toBytes`/`fromBytes` round trip before the facade validates, then broadcast with consensus refusals reworded. See the identifier-media gotcha.
- **Document shapes** — `toDocumentArray` in [safeDoc.ts](src/lib/safeDoc.ts) flattens whatever `query` returns (array, `Map`, plain object); `requireId` in [ids.ts](src/dash/ids.ts) validates every identifier crossing a boundary.

## Performance — load-anchor rules

Same as the sibling apps: the `@dashevo/evo-sdk` browser bundle is ~8 MB and must stay off the boot critical path. **Never add a top-level value import from `@dashevo/evo-sdk`** to any file reachable from `App.tsx` — go through [sdkModule.ts](src/dash/sdkModule.ts)'s cached dynamic import (type-only imports are fine). The shared core is loaded via [sdkCore.ts](src/dash/sdkCore.ts)'s `loadSdkCore()` — two distinct loaders, don't merge. The `modulePreload.resolveDependencies` filter in [vite.config.ts](vite.config.ts) strips the `evo-sdk` chunk so Vite doesn't inject a `<link rel="modulepreload">` that re-blocks first paint. The synchronous exports of [contractStore.ts](src/dash/contractStore.ts) must stay synchronous — they run during initial render before the SDK loads.

## Gotchas

- **Identifier query filters must be base58 strings, never `Uint8Array`.** The document-query filter passes through JSON deserialization; a byte array fails with `Invalid documents query: fromObject: serde deserialization error: invalid type: byte array, expected any valid JSON value`. Verified on testnet against Keyword Search's `shortDescription`.
- **Identifier-media `Document` _properties_ also need canonical base58, then a round trip.** Passing a `Uint8Array` — or a plain number array — for `contractId` on a write fails in Drive with `structure error: not an array of bytes`. The evo-sdk contract-aware serializer wants base58 at the boundary, then a fetched-contract `toBytes`/`fromBytes` round trip to produce the typed identifier before facade validation. Because that serializes before the facade populates timestamps, `prepare` seeds create timestamps and preserves `$createdAt` while advancing `$updatedAt` on replace; because `fromBytes` drops wrapper-only creation entropy (`Document must have entropy set for creation`), it restores the draft's entropy after the round trip. Don't unwind either step.
- **Grouped `count`/`average` map keys are raw index-key bytes, NOT the value.** For `stars` that is the plain value byte (5 stars → `"05"`, [dashpay/platform#5350](https://github.com/dashpay/platform/pull/5350)); for `contractId` it is the identifier's 32 bytes in hex, which `idFromKeyHex` converts to base58. `ranked`/`having` entries instead carry a decoded base58 `groupValue`. Decode the keys that come back — an unrecognized key rejects the result as malformed rather than reading as zero; don't encode the expected keys and look them up. Tests use literal network-format results for the same reason.
- **Aggregates omit empty groups.** An ungrouped `average` or `count` with no matching documents returns an empty map, and a grouped one leaves out contracts or star values with none, so every reader zero-fills. The histogram also needs its `stars between [1,5]` range: grouping without it is refused.
- **`ranked` ties are unordered.** Contracts with equal averages or counts come back in no meaningful order, so don't present ties as ranked.
- **A `startAfter` cursor is a live document, not a position.** If the last-shown document was deleted, "Load more" fails with `StartDocumentNotFound`; if it was edited (e.g. a 5★ rating changed to 1★ under "Highest"), the next page resumes from its new position. Reloading the list starts over.
- **The network sorts `desc` server-side.** Older Platform releases ignored it and returned ascending results.
- **Count index flags are fussy.** `rangeCountable` is separate from `countable` and needs the range field as the **last** index property — a `countable`-only index fails at query time. And never mix `summable` with a count-only index on a shared prefix: it registers fine but breaks every document insert ([dashpay/platform#3960](https://github.com/dashpay/platform/issues/3960)). A ranked index may not extend a countable or summable index by one property, so `contractStars` stays unranked beside the averageable `contractRating`; [test/contractSchema.test.ts](test/contractSchema.test.ts) encodes that rule.
- **Read errors need care in both directions.** SDK errors can be WASM objects with a `message()` method, so use `errorMessage` from [logger.ts](src/lib/logger.ts) rather than `String(error)` — including before wrapping one. And a failed read is not an empty one: Keyword Search short descriptions fail independently of successfully loaded contract facts, so show that field's own error beside it and let Refresh retry, rather than rendering it as absent.
- **Unique-index violations (40105) are an edit prompt, not a failure.** `createMetadata` checks for an existing owner/contract pair first; `saveRating` and `endorse` resolve a 40105 race by re-reading and replacing.
- **References are checked on create and replace, never on delete.** A missing contract or publisher entry is 40120, a failed owner requirement is 40135, and changing an immutable `contractId` is 40128; `explainWriteError` rewords each. A publisher can withdraw their entry after being endorsed, leaving a dangling endorsement: `officialListing` returns it with `entry: null`, and replacing it without changing `publisherId` fails with 40120 — re-point or delete it instead.
- **Session state is generation-guarded, and secrets never enter it.** [SessionContext.tsx](src/session/SessionContext.tsx) invalidates connection/auth/balance on network change and resets dependent views and pending sign-in on registry change (an already-authenticated identity stays signed in); registry selection survives a network switch in memory even when `localStorage` is unavailable, and mainnet sign-in is rejected in the session API, not only hidden in the UI. Recovery phrases and WIFs are passed to login as parameters and cleared from the form immediately — never put them in React state, refs, storage, or logs.
- **Shared auth files are byte-identical across apps.** `src/dash/loginWithPrivateKey.ts`, `src/lib/detectSecretShape.ts`, `src/session/keyManagerFromKey.ts`, and `test/loginWithPrivateKey.test.ts` match Dashnote and TokenOps exactly; CI enforces it with [scripts/check-shared-auth-parity.sh](../../scripts/check-shared-auth-parity.sh) (run from the repo root). Keep app-specific session and form behavior out of those four files.
- The Evo SDK WASM bundle is ~8 MB; that's expected, not a build error. See [Performance](#performance--load-anchor-rules).
